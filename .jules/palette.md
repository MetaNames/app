## 2024-10-24 - Accessible Icon Props and Loading Button State
**Learning:** Svelte wrapper components (like `Icon.svelte`) must spread `$$restProps` to allow passing accessibility attributes (e.g., `aria-label`) from parent components. Without this, icons remain inaccessible to screen readers. Also, persistent "Success" states on buttons can be confusing; auto-resetting them after a timeout improves clarity.
**Action:** Always include `{...$$restProps}` in wrapper components and implement auto-reset logic for temporary success states in interactive elements.
## 2024-10-25 - Conditional Rendering of Trailing Icons in SMUI Textfields
**Learning:** When using SMUI `Textfield` components with a trailing icon (like a clear button), the `withTrailingIcon` property strictly expects a boolean. If you conditionally render the icon element itself using `{#if ...}`, you must simultaneously bind `withTrailingIcon` to the identical boolean condition. Otherwise, the component will still reserve layout space for the icon, and worse, focus states or accessibility semantics may break if the icon element is statically present but visually hidden. Additionally, always use descriptive `aria-label`s on such icons (e.g., "clear search" rather than a generic "cancel").
**Action:** Always synchronize the `withTrailingIcon` boolean property with the `{#if ...}` condition used to render the actual icon fragment in SMUI Textfields, and ensure precise `aria-label`s are applied.
